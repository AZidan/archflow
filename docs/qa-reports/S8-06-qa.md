## Findings

### I-1 (minor): misleading messages while an environment variable disables telemetry
- **Location:** `scripts/archflow.mjs:494` (new in this story); also `scripts/archflow.mjs:486` and `plugin/hooks/telemetry.mjs:196` (output from S8-05, which this story now has every host relay word for word).
- **Repro:** `DO_NOT_TRACK=1 npx archflow telemetry` prints
  `Anonymous usage telemetry: off (DO_NOT_TRACK is set in the environment; nothing is sent while it is). \`archflow telemetry on\` to turn it on.`
  Then `DO_NOT_TRACK=1 npx archflow telemetry on` (or `/archflow:telemetry on` on any host) prints
  `Anonymous usage telemetry is now ON.`
- **Expected:** while the variable is set, the hint should say to unset it, and `on` should say the
  stored choice is on but nothing is sent while the variable is set.
- **Actual:** the hint suggests a command that cannot turn telemetry on. Because the command files now
  say to relay output **verbatim**, the agent tells the user "now ON" when telemetry is still off.
  It fails safe, since nothing is sent either way, so this is not blocking.

### Observations (not filed)
- `plugin/commands/telemetry.md` `argument-hint: "[on|off]"` and the Codex skill's `Arguments: [on|off]`
  don't mention `status`, although the files accept it.
- The release file still has the S8-06 subtask "CLI telemetry subcommand tests" as `completed: false`,
  but `tests/test_telemetry_command.py` covers it. That is for the implementer to update.
