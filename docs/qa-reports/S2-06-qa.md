## Findings

### I-1 (minor): generated help advertises `studio` on hosts that do not have it

- Location: `plugin/commands/help.md:52`, rendered into every adapter's help.
- Every host in `scripts/build-adapters.mjs` sets `skip: new Set(["studio"])` (lines 370, 534,
  671, 763, 841, 932), so no `archflow-studio` command or skill is generated. Yet
  `adapters/codex/.agents/skills/archflow-help/SKILL.md:56` lists `$archflow-studio` and
  `adapters/gemini/commands/archflow/help.toml:52` lists `/archflow:studio`; the same holds for
  copilot, cursor, generic and opencode.
- Expected: help on a host lists only the commands that host has (or marks studio "not available",
  as each adapter's `AGENTS.archflow.md` table already does). Actual: a user on Codex/Gemini/etc.
  is told to run a command that does not exist.
- Note: the old status command list had the same problem, so this is inherited. But help is now
  the reference whose whole job is "every command you can run", so it matters more here.

### I-2 (minor): help's "full instructions are in …" pointer is a dead path on five hosts

- Location: `plugin/commands/help.md:10`, rewritten by the `${CLAUDE_PLUGIN_ROOT}` vocab rule
  in `scripts/build-adapters.mjs` (e.g. line 391 for codex).
- Rendered: `.codex/archflow/commands/<name>.md`, `.github/archflow/commands/<name>.md`,
  `.agents/archflow/commands/<name>.md`, `.cursor/archflow/commands/<name>.md`,
  `.opencode/archflow/commands/<name>.md`. None of those adapters ships a `commands/` directory
  under `<host>/archflow/` (contents are `hooks lib scripts skills`). The real files are
  `.agents/skills/archflow-<name>/SKILL.md` (codex/generic), `.github/skills/archflow-<name>/SKILL.md`
  (copilot) and `.cursor/commands/archflow-<name>.md` / `.opencode/commands/archflow-<name>.md`.
  Gemini is correct (it has a dedicated rewrite to the `.toml`, line 550).
- Same systemic pattern exists in other commands (autopilot, feature, init, release reference
  `<host>/archflow/commands/*.md`), so the root cause is the adapter vocab, not help.md. Help
  adds a new user-facing instance.

### I-3 (minor): help takes an argument but declares no `argument-hint`

- Location: `plugin/commands/help.md:1-3`.
- help.md handles `$ARGUMENTS` naming a command (prints just that line), and the CHANGELOG
  advertises `/archflow:help <command>`, but the frontmatter has only `description`. Every other
  command that takes arguments declares an `argument-hint`, so the picker shows nothing here.
  Expected e.g. `argument-hint: "[command]"`.
