## Gemini: paths and reference rewrites

- **Every extension path resolves.** All 23 distinct `$HOME/.gemini/extensions/archflow/...` paths
  across commands, agents, skills, `GEMINI.md` and JSON resolve with `test -e "<path>"` under the temp
  HOME. The only non-resolving match is the literal placeholder `commands/archflow/<name>.toml` in
  `SKILL.md`, which is a template. Its directory exists.
- **Every shell block that names the extension runs.** That covers doctor (validate, upgrade check,
  upgrade apply, git guard), telemetry (`--status`, `--enable`) and migrate. None failed on the path.
  migrate's `--dry-run` line failed only on its `<project-root>` placeholder, which is documentation
  text the model fills in, not a path defect.
- **Rewrites point at real files and only at the intended text.** The source plugin has 12
  `${CLAUDE_PLUGIN_ROOT}/commands/<x>.md` references (design×4, groom×4, onboard, setup-mcp, status,
  `<name>`). The Gemini package has exactly 12 matching `commands/archflow/<x>.toml` references and
  no remaining `commands/<x>.md` reference, apart from the `# Generated from plugin/commands/...`
  file headers, which are correct. The rule runs before the general `${CLAUDE_PLUGIN_ROOT}` rule, so
  every other path is still rewritten to the plain `$HOME` prefix. The diff to the generated files
  is limited to those 12 lines. No `~/.gemini` survives in any prompt. The one remaining occurrence,
  in `adapters/gemini/README.md`, is unquoted human documentation.
- `hooks/hooks.json` and `gemini-extension.json` still use `${extensionPath}`, which Gemini does
  substitute there, so the change correctly leaves them alone.

## Cursor bridge: payload shapes and stdout

- Covered by tests and re-checked by hand: a single root; multiple roots with the project first,
  not first, and two Archflow roots (the first wins); no Archflow root (plain workspace, every gate
  open, telemetry `has_project: false`); an explicit `cwd` overriding roots; no roots, `[]`, `null`,
  `[null, 3]`, empty stdin and garbage stdin (graceful no-op on all four events). Extra probes:
  `42`, `"x"`, `[]` and `{"workspace_roots":"/tmp"}` all exit 0 with valid JSON on stdout.
- **The stderr relay leaves stdout intact.** On `stop`, the drift advisory goes to the bridge's
  stderr (`console.error`) and stdout is exactly `{}`. `test_stop_surfaces_state_drift_for_the_resolved_project`
  parses stdout as JSON and asserts the advisory text on stderr. `check-state.mjs` writes its
  advisory only to stderr (line 51), so the fix matches it, and the `|| r.stdout` fallback keeps the
  old path.
- Observation, not recorded: a stdin of the JSON literal `null` makes the bridge throw at the
  `input.workspace_roots` line (exit 1, no stdout). 2.4.0 threw at `input.cwd` on the same input, so
  this is not a regression, and Cursor always sends an object.
