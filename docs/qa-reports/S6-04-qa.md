### Ruling: Gemini `extensions update` path, recorded as I-6 (blocking)

`installGeminiFrom` (`scripts/archflow.mjs:533-549`) handles "already installed" by running `gemini extensions update archflow`. Gemini CLI records an extension's install source in its install metadata, and for a local-path install `update` re-copies from that recorded path. It does not use the newly staged folder. The installer itself says so in its comment at `scripts/archflow.mjs:527`. So, for every existing Gemini CLI user upgrading:
- **From 2.4.0:** 2.4.0 ran `gemini extensions install <package or release cache>/adapters/gemini` (`git show 2.4.0:scripts/archflow.mjs`, `installGemini`). That source has no `server/` or `dist/`, because the bundle is staged separately by `installStudio`. Depending on what sits at the path now, the update reinstalls the 2.4.0 extension (no studio command at all), reinstalls the current adapter without the bundle, or reports "up to date" and changes nothing. In none of these cases does the bundle reach `~/.gemini/extensions/archflow`.
- **From 2.5.0 onward:** the recorded source is `~/.cache/archflow/gemini-extension/<old version>/archflow`, which the update path deliberately keeps. The update reinstalls the old version.
- The installer still prints `copy ~/.gemini/extensions/archflow/server/server.mjs, .../dist/ (Archflow Studio)` on this path (seen in the fake-gemini run), which is false. `/archflow:studio` then reports the bundle missing, and its remedy, `npx archflow@latest install`, goes through the same update path. That is the I-3 loop again, on Gemini.

This makes the criterion "npx archflow install copies the bundle for each host" false for a realistic case: any Gemini user who installed through the Gemini CLI before. This was assessed from the code and Gemini's documented install-metadata behaviour. The local Gemini CLI (0.1.7) predates `extensions install/update`, and nothing was installed to check it. Direction for the fix (not applied): on "already installed", run `gemini extensions uninstall archflow` and then install from the staged path, or fall through to the direct copy. Then pruning can run on every path.
