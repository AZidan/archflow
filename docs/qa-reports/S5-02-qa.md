## Issues

### I-1 (blocking): an aborted run with parked stories is a dead end

- **Location:** plugin/commands/autopilot.md:248-251 (the `Next:` rule), :314 (resume refuses aborted runs), :319 (`abort` prints Step 4), and plugin/commands/status.md:34.
- **Repro (by reading the spec):**
  1. A run parks S1-02, then the user runs `/archflow:autopilot abort`.
  2. `abort` sets `status: aborted` and prints Step 4. Step 4's rule is "With parked stories it is the line above", so the report says `Next: /archflow:autopilot resume — asks the parked questions...`.
  3. The user runs it. Resume rule 3 says "An `aborted` run is never resumed", so it prints `Nothing to resume.`
  4. `/archflow:status` case 3 still tells the user to run `/archflow:autopilot resume` for S1-02, unconditionally.
- **Expected:** the report and status name a command that actually brings S1-02 back. That is the exact contract this story set for finished runs.
- **Actual:** S1-02 stays `parked` and no command leads anywhere. Step 1 excludes `parked` from the default queue, and nothing documents how an explicit-id run clears a `parked` block. Abort is documented as bookkeeping that leaves state intact, so it is the common way to end up here.
- **Fix options (for the implementation agent to choose):**
  - Let rule 2 also start a follow-on run over an *aborted* run's still-parked stories. The aborted ledger stays aborted, so "aborted runs stay aborted" still holds for the run itself.
  - Or give abort's `Next:` line, and status case 3, a working alternative. It would need its own documented exit from `parked`.
- **Test:** `tests/test_autopilot_resume_qa.py::test_abort_report_next_line_names_a_command_that_works_for_an_aborted_run` (strict xfail).

### I-2 (minor): follow-on resume does not check the release

- **Location:** plugin/commands/autopilot.md:296-308.
- **Problem:** rule 2 checks that a story is "still `status: parked` in the release file" but never says which file, and never checks that the finished ledger's `release` is still `active_release`.
- **Why it matters:** a release may ship with a non-blocking parked story (`blocks_release: false`) and be archived. Resume would then edit an archived or other release file, which the hard constraints forbid ("Touch ... any other release file").
- **Also:** rule 2 does not restate that the Prerequisites (clean tree, phase ≥ 3) apply before writing the new ledger. Rule 1 does not restate them either, but rule 2 writes state.
- **Expected:** skip, or report, parked stories whose release is no longer active.

### I-3 (minor): a stale preflight ledger outranks parked work

- **Location:** plugin/commands/autopilot.md:292.
- **Problem:** rule 1 selects the newest `preflight` or `running` ledger at any age, before rule 2 looks at finished runs. Take a `--plan` ledger that was never started, plus a finished run with parked stories. A user following status case 3 ("answer the parked question via resume") instead starts the old planned queue unattended, and the parked question is not asked.
- **Context:** this precedence existed before the story, but the story now routes every parked story through `resume`.
- **Expected:** state the precedence explicitly in the status advice, or have rule 1 also gather finished runs' still-parked stories.

### I-4 (minor): landing page keeps the old wording

- **Location:** docs/index.html:680.
- **Problem:** the page still says "Answer, then `/archflow:autopilot resume` picks up where it stopped". That is the two-step phrasing the story removed from README and status. The uncommitted `docs/index-next.html:691` has the same line.
- **Expected:** match README:198. Resume asks the questions itself, and it works after a run finished.

## Other scrutiny (no issue raised)

- **Reaching past a newer finished run with nothing parked to an older one:** sound. Each queue item is cross-checked against the release file, so stories resolved by a later follow-on drop out. When two finished runs both hold parked stories, it takes successive `resume` calls (newest run first), but each call makes progress.
- **Parked story un-parked by hand:** handled by the "still `status: parked`" cross-check and by rule 3's "(or whose parked stories have all been resolved since)".
- **Run branch merged and deleted:** a fallback to `base_branch` is documented. The WIP task branches were cut from the old run branch, and merging them into the new run branch is safe once the old branch is merged into base.
- **Guard hook:** arms only on `running` or `preflight`, so a finished parent never arms it and a follow-on does. Both are tested.
- **Validator:** skips finished and aborted ledgers (validate_archflow.py:300-314).
- **Release schema:** `parked` → `in_progress` is the documented exit, and rule 2 uses it.
