## Findings

### I-1 (minor): a HOOK_SCRIPTS entry ships a hook but does not activate it on any host

- **Location:** `scripts/build-adapters.mjs:123` (the claim). Per-host wiring is at about lines
  279-304 (bridge), 411-422 (codex), 558-569 (gemini), 775 (generic prose) and 940-951 (copilot).
- **Expected (AC1 text):** "Adding a hook requires only a HOOK_SCRIPTS entry."
- **Actual:** the entry copies the script into every adapter, and that part works (see above). But
  each host decides which scripts run, and on which events, in its own hand-written table. A new
  hook with only a `HOOK_SCRIPTS` entry ships to every adapter and never runs. Nothing tests the
  wiring either: the probe passed every test while wired to nothing.
- **Mitigation already present:** the doc comment says "Wiring a hook into a host's own hooks file
  (event names, matchers, timeouts) stays per-host by nature". The story description scopes the
  work to copying the runtime.
- **Why minor:** the scoped deliverable (one helper, one list) is correct and guarded. The gap is
  that the AC wording promises more than the build delivers. Two ways to close it are rewording AC1
  to "ships a hook to every adapter", or deriving the wiring from a shared event map. Which one is
  the user's call.
