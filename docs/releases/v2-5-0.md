# Archflow 2.5.0 (v2-5-0)

Released 2026-10-13.

Telemetry on every host with a one-command opt-out, adapter build and host fixes, and the Studio-first site repositioning.

## Stories

### S8-07: Record telemetry policy: on by default (opt-out), framework-wide

- A new ADR records opt-out, framework-wide telemetry (scope, event allow-list, DO_NOT_TRACK/CI disable, notice, opt-out command) and marks ADR 003 superseded
- SECURITY.md states that anonymous telemetry is on by default, what is sent, what is never sent, and how to turn it off
- CHANGELOG [Unreleased] describes the same default and opt-out

### S8-05: Framework-wide anonymous telemetry

- No event carries project names, paths, file contents, prompts or arguments
- DO_NOT_TRACK and CI disable telemetry and send nothing
- Telemetry is on by default (opt-out) on every host, per S8-07
- A one-time notice announces telemetry

### S8-06: /archflow:telemetry and npx archflow telemetry

- /archflow:telemetry [on|off] works on every host
- After opt-out no further events are sent

### S7-04: build-adapters HOOK_SCRIPTS helper

- Adding a hook requires only a HOOK_SCRIPTS entry
- build-adapters.mjs --check passes

### S7-05: Gemini $HOME path and Cursor workspace-root fixes

- Gemini /archflow:doctor resolves the plugin path (automated test; live check by user)
- Cursor hooks find the project without cwd (automated test; live check by user)

### S9-04: Studio-first site repositioning

- Homepage hero leads with Studio
- Studio guide matches current Studio behavior
- Page states which hosts Studio supports, consistent with the CHANGELOG
- Page passes the archflow-marketing guardrails (no pricing hints, no total command count, one-argument marketplace command, install command present)

### S2-06: /archflow:help command; status drops the command list

- plugin/commands/help.md lists every command in plugin/commands/ with a one-line usage note, plus a short primer on how Archflow works
- /archflow:status no longer prints the command list; it ends with the suggested next command(s) and a pointer to /archflow:help
- A test checks that help lists exactly the commands in plugin/commands/, so the list cannot drift
- Every place that lists commands includes help: CLAUDE.md, README.md, instructions.md, reference.md, SKILL.md (mirrored in .archflow/), docs guides, site
- Gemini adapters regenerate with help.toml and build-adapters.mjs --check passes
- Telemetry's command allowlist (plugin/lib/telemetry.mjs) recognises help, if it keeps one
- CHANGELOG has an entry for the change

### S5-02: Resume parked work after an autopilot run finishes

- After a run finishes with parked stories, there is one documented command that picks them up once their questions are answered
- The end-of-run report's 'Next:' line names a command that actually works for a finished run
- /archflow:status's parked-story advice matches the real resume path
- A run with no parked stories is not resurrected by resume; aborted runs stay aborted
- Tests cover resume on a finished run with parked stories, one without, and an aborted run
- CHANGELOG has a Fixed entry

### S6-04: Studio on non-Claude hosts (forward mode)

- The rebuilt forward-mode bundle (plugin/server/server.mjs, plugin/dist/**, hooks.json) is committed
- Every adapter ships /archflow:studio and the server bundle it needs; build-adapters.mjs no longer skips studio
- /archflow:studio starts, reports status and stops Studio on a non-Claude host, launching the server from the adapter's own copy
- studio.md describes forward mode and per-host behaviour accurately; no 'not built yet' or Claude-only claims remain
- help, SKILL.md and reference.md list studio on every host, consistent with what each adapter ships
- npx archflow install copies the bundle for each host; the npm package stays a sensible size
- build-adapters.mjs --check passes and tests cover the shipped bundle per host
- CHANGELOG supersedes the 2.4.0 'Claude Code only' line; the site's host claims match
